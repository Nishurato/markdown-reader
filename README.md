# Markdown Reader

Markdown Reader 0.2.3 — настольная читалка Markdown. Для чтения локальных файлов соединение с интернетом не требуется.

Приложение использует C++20, Qt 6.8+ Widgets, QTextDocument и QTextBrowser. Сборка выполняется через CMake 3.21+ и Ninja, автоматические тесты запускаются через CTest и Qt Test.

## Возможности

- Открытие файлов `.md` и `.markdown` кнопкой «Открыть файл» на стартовой странице, горячей клавишей или передачей пути при запуске.
- Чтение UTF-8, в том числе с BOM. При ошибке приложение показывает сообщение и сохраняет открытый документ.
- Заголовки H1–H6, жирное и курсивное начертание, списки, цитаты, блоки кода, таблицы, горизонтальные разделители, ссылки и локальные изображения.
- Дерево заголовков с переходом по щелчку или клавишей Enter. Одинаковые названия различаются по позиции в документе.
- Боковая панель при запуске скрыта. Переключатель слева под вкладками показывает заголовки активного документа и восстанавливает ширину панели. Ширину можно изменить разделителем.
- Кнопка «+» создаёт вкладку со стартовой страницей. Файл открывается в текущей стартовой вкладке или в новой, если текущая уже занята. Вкладки можно перетаскивать и закрывать. Подсказка показывает полный путь, а при переключении сохраняются документ и позиция прокрутки. После закрытия последней вкладки снова появляется стартовая страница.
- Документ расположен по центру области чтения на светлой странице шириной 800 логических пикселей с внутренними отступами 40 px. В узком окне страницу можно прокручивать горизонтально.
- Ссылки на другие локальные Markdown-файлы разрешаются относительно файла вкладки и открываются в новой вкладке. HTTP и HTTPS открываются системным браузером по щелчку.
- Ссылка `#раздел` прокручивает текущий документ, а `guide.md#раздел` открывает файл в новой вкладке и прокручивает её. Якоря берутся из H1–H6. В идентификаторах сохраняются буквы, цифры, дефисы и подчёркивания, пробелы заменяются дефисами. Фрагмент URL декодируется, поиск идёт без учёта регистра. Дубликаты получают суффиксы `-1`, `-2` и далее. Пустой фрагмент ведёт к началу документа, неизвестный якорь показывает сообщение в строке состояния.

Откройте [демонстрационный документ](examples/example.md), чтобы увидеть форматирование и проверить навигацию.

| Действие | Windows и Linux | macOS |
| --- | --- | --- |
| Новая вкладка | Ctrl+T | ⌘T |
| Закрыть вкладку | Ctrl+W | ⌘W |
| Следующая вкладка | Ctrl+Tab | Ctrl+Tab |
| Предыдущая вкладка | Ctrl+Shift+Tab | Ctrl+Shift+Tab |
| Открыть файл | Ctrl+O | ⌘O |

На macOS переключение вкладок использует физическую клавишу Control, поскольку ⌘Tab переключает приложения.

## Сборка и запуск

Для сборки нужны CMake 3.21+, Ninja, компилятор C++20 и соответствующий ему комплект Qt 6.8+ с модулями Widgets и Test. Qt Test требуется при включённом `BUILD_TESTING` (по умолчанию). Для сборки только приложения передайте `-DBUILD_TESTING=OFF` на этапе конфигурации. Используйте отдельный каталог сборки при смене компилятора.

### Windows 10/11, MSVC x64

Установите компоненты Visual Studio «Разработка классических приложений на C++», Windows SDK и Qt для **MSVC x64**. Откройте **Developer PowerShell for VS** в профиле x64. CMake и Ninja должны быть в PATH. Замените путь к Qt на путь к установленному комплекту.

```powershell
$qt = "C:/Qt/6.8.3/msvc2022_64"
$env:Path = "$qt/bin;$env:Path"
cmake --preset release "-DCMAKE_PREFIX_PATH=$qt" -DCMAKE_CXX_COMPILER=cl
cmake --build --preset release
ctest --preset release
.\build\release\MarkdownReader.exe .\examples\example.md
```

Запускайте приложение из этой оболочки, чтобы оно находило библиотеки Qt.

### macOS, Intel или Apple Silicon

Установите инструменты Xcode (`xcode-select --install`), CMake, Ninja и Qt для архитектуры компьютера. Укажите префикс своего Qt.

```sh
cmake --preset release -DCMAKE_CXX_COMPILER=clang++ -DCMAKE_PREFIX_PATH="$HOME/Qt/6.8.3/macos"
cmake --build --preset release
ctest --preset release
./build/release/MarkdownReader.app/Contents/MacOS/MarkdownReader examples/example.md
```

### Linux x86-64, GCC

Установите GCC, CMake, Ninja, Qt 6.8+ для x86-64 и системные зависимости графического плагина Qt для вашего дистрибутива. Укажите префикс своего Qt. Для Qt, установленного в стандартный системный префикс, `CMAKE_PREFIX_PATH` можно опустить.

```sh
cmake --preset release -DCMAKE_CXX_COMPILER=g++ -DCMAKE_PREFIX_PATH="$HOME/Qt/6.8.3/gcc_64"
cmake --build --preset release
ctest --preset release
./build/release/MarkdownReader examples/example.md
```

Тесты используют платформенный плагин Qt `offscreen`. Обычный запуск приложения использует нативный графический плагин Qt.

## Cross-Platform Builds

Workflow [Cross-Platform Builds](.github/workflows/build.yml) собирает Release через CMake и Ninja с Qt 6.8.3. Каждый runner запускает CTest и проверяет развёртывание перед загрузкой пакета. Пакеты и отдельные журналы `tests-*` хранятся до 14 дней. Workflow запускается вручную и для pull request.

| GitHub runner | Компилятор | Файл внутри артефакта |
| --- | --- | --- |
| `windows-2022` | MSVC 2022 x64 | `MarkdownReader-0.2.3-Windows-x64.zip` |
| `ubuntu-22.04` | GCC x86_64 | `MarkdownReader-0.2.3-Linux-x86_64.AppImage` |
| `macos-15-intel` | Apple Clang x86_64 | `MarkdownReader-0.2.3-macOS-Intel.dmg` |
| `macos-15` | Apple Clang arm64 | `MarkdownReader-0.2.3-macOS-ARM64.dmg` |

Для ручного запуска откройте вкладку **Actions**, выберите **Cross-Platform Builds**, затем **Run workflow** и ветку. Кнопка ручного запуска доступна после появления workflow в ветке по умолчанию. После завершения откройте страницу прогона и скачайте нужный пакет в разделе **Artifacts**. Распакуйте внешний ZIP от GitHub Actions, чтобы получить файл из таблицы. При сбое скачайте соответствующий артефакт `tests-*` и проверьте лог задания.

### Запуск тестового пакета

**Windows x64.** Распакуйте внутренний ZIP в отдельный каталог. Запустите `MarkdownReader.exe`, сохранив рядом DLL Qt и каталоги `platforms` и `imageformats`. Если отсутствует среда выполнения MSVC, установите официальный [Visual C++ Redistributable x64](https://learn.microsoft.com/cpp/windows/latest-supported-vc-redist). Qt 6.8 указывает Windows 10 1809 и новее, а также Windows 11. Для диагностики плагинов задайте `$env:QT_DEBUG_PLUGINS = "1"` и запустите приложение из PowerShell. Если вывод недоступен в консоли, используйте журнал Windows или DebugView. [Поддерживаемые платформы Qt 6.8](https://doc.qt.io/qt-6.8/supported-platforms.html)

**macOS.** Выберите DMG по результату `uname -m`: Intel для `x86_64`, ARM64 для `arm64`. Откройте DMG и перетащите `MarkdownReader.app` в Applications. Тестовый пакет имеет локальную подпись ad hoc. Gatekeeper может ограничить запуск загруженного файла, поскольку подпись Developer ID и нотариализация пока отсутствуют. При сбое приложите вывод `sw_vers`, `uname -m`, `lipo -archs /Applications/MarkdownReader.app/Contents/MacOS/MarkdownReader` и `otool -L` для этого же файла.

**Linux x86_64.** Пакет включает библиотеки Qt и плагины XCB и изображений. Нужен X11 или XWayland и системные библиотеки дистрибутива. Ориентир совместимости — Ubuntu 22.04 с glibc 2.35. На более старых дистрибутивах запуск не подтверждён.

```sh
app=./MarkdownReader-0.2.3-Linux-x86_64.AppImage
chmod +x "$app"
"$app"
# Запуск без FUSE
"$app" --appimage-extract-and-run
# Диагностика зависимостей и плагина XCB
"$app" --appimage-extract
ldd squashfs-root/usr/bin/MarkdownReader squashfs-root/usr/plugins/platforms/libqxcb.so
QT_DEBUG_PLUGINS=1 QT_QPA_PLATFORM=xcb ./squashfs-root/AppRun
```

Приложите строки `not found` из `ldd`, вывод `ldd --version` и `cat /etc/os-release`. На Ubuntu и Linux Mint для XCB может понадобиться, в частности, пакет `libxcb-cursor0`. [Системные зависимости Qt для Linux](https://doc.qt.io/qt-6/linux-requirements.html)

Если инструмент создания AppImage недоступен, после сборки и CTest тот же сценарий может упаковать подготовленный каталог в переносимый архив:

```sh
bash .github/scripts/package-linux.sh build/release "$HOME/Qt/6.8.3/gcc_64" 0.2.3 \
  build/packages/MarkdownReader-0.2.3-Linux-x86_64.tar.gz
tar -xzf build/packages/MarkdownReader-0.2.3-Linux-x86_64.tar.gz
./MarkdownReader.AppDir/AppRun
```

## Проверка в VMware

В гостевой системе поместите исходники в локальный каталог, установите подходящий комплект Qt 6.8+ и выполните команды сборки и CTest из раздела выше. Для проверки стартовой страницы запустите приложение **без** аргумента `examples/example.md`.

| Гостевая система | Что записать перед проверкой |
| --- | --- |
| Windows 10 | Выполните `winver`, проверьте архитектуру x64 в Developer PowerShell и версию компилятора через `cl`. Версию Qt выведет `& "$qt/bin/qtpaths.exe" --query QT_VERSION`. |
| macOS | Выполните `sw_vers`, `uname -m`, `clang++ --version` и `"$HOME/Qt/6.8.3/macos/bin/qtpaths" --query QT_VERSION`, подставив путь к своему Qt. Запишите `x86_64` или `arm64`. Результат относится только к этой архитектуре. |
| Linux | Выполните `cat /etc/os-release`, `uname -m`, `g++ --version` и `"$HOME/Qt/6.8.3/gcc_64/bin/qtpaths" --query QT_VERSION`, подставив путь к своему Qt. При ошибке GUI запустите приложение с `QT_DEBUG_PLUGINS=1` и проверьте зависимости `xcb` для X11/XWayland или наличие плагина Wayland для соответствующего сеанса. |

Чек-лист ручной проверки после успешных сборки и CTest:

1. Запустите приложение. Убедитесь, что видна стартовая страница с кнопкой «Открыть файл». Откройте диалог и отмените выбор. Страница должна остаться на месте.
2. Откройте `examples/example.md` кнопкой и проверьте локальное изображение, форматирование, панель заголовков и прокрутку. Файл должен занять ту же вкладку.
3. Нажмите ссылки «Форматирование в этой вкладке» и «Второй одноимённый раздел». Убедитесь, что меняется позиция прокрутки, а число вкладок сохраняется.
4. Нажмите «Сборка и запуск в README». Должна открыться новая вкладка на разделе сборки. Вернитесь в пример и проверьте прежнюю позицию прокрутки.
5. Проверьте `+`, крестик, Ctrl+O/T/W или ⌘O/T/W и переключение вкладок физическими Ctrl+Tab и Ctrl+Shift+Tab. На macOS отдельно проверьте, что Option+O/T/W не вызывает эти команды, а ⌘Tab переключает приложения. Закройте последнюю вкладку и проверьте появление стартовой страницы.
6. Проверьте маркированный и нумерованный списки. Выделите текст от строки перед списком до второго пункта, снимите фокус с окна и верните его. Маркеры и текст должны оставаться читаемыми. Скопируйте выделение через Ctrl+C или ⌘C и вставьте в текстовый редактор. Проверьте прокрутку колесом и клавишами Page Up/Page Down.

Для каждой системы запишите результат сборки, вывод CTest и результат каждого шага GUI. На Linux Mint, если маркер трудно различить, сравните запуск в обычной теме и с `QT_STYLE_OVERRIDE=Fusion` перед командой запуска пакета. Приложите снимки выделения в активном и неактивном окне, вывод `cat /etc/os-release`, имя темы и значения `XDG_CURRENT_DESKTOP`, `XDG_SESSION_TYPE`, `QT_QPA_PLATFORMTHEME` и `QT_STYLE_OVERRIDE`.

Для проверки готового артефакта перенесите в гостевую ОС пакет и папку `examples/` вместе с `README.md`, чтобы относительные ссылки примера работали. Запустите приложение по инструкции выше, повторите чек-лист и заполните таблицу отдельно для каждой архитектуры.

## Производительность

[Методика и результаты измерений](docs/performance.md) описывают генератор файлов объёмом 1 МиБ, замер первого отображения и память с одной и пятью вкладками.

## Изменения в 0.2.3

- Windows CI обнаруживает Visual Studio через `vswhere.exe` из PowerShell и настраивает MSVC x64 через Developer PowerShell. Это устраняет ошибку разбора пути с пробелами.
- На Linux рендерер сохраняет фон выделения из темы и повышает контраст текста и маркеров, если выбранные темой цвета трудно различить.
- Добавлены воспроизводимые измерения времени отображения и памяти. Измерительный исполняемый файл собирается отдельно.

В 0.2.3 локально прошли сборка, CTest и проверка пакетов на Windows 11 24H2 x64 и Ubuntu 22.04.5 x86_64 в WSL2. Linux-тест маркера также прошёл через XCB под Xvfb. Новый прогон GitHub Actions и ручные проверки в гостевых ОС пока не выполнены.

## Ограничения версии 0.2.3

- Форматирование определяется [QTextDocument](https://doc.qt.io/qt-6/qtextdocument.html#setMarkdown) в режиме `MarkdownDialectGitHub`. Встроенный HTML отключён. Полное совпадение с отображением на GitHub не предполагается.
- В Qt 6.8.3 первая ячейка заголовка таблицы сразу после блока кода может отображаться ниже соседних ячеек.
- Загружаются изображения из локальных файлов в форматах, поддерживаемых установленными плагинами Qt. Для удалённых изображений отображается альтернативный текст, если он указан.
- Сопоставление якорей использует отображаемый Qt текст заголовков. Встроенные HTML-якоря и явные идентификаторы заголовков не поддерживаются.
- Блоки кода отображаются без языковой подсветки. Открытые вкладки и прокрутка сохраняются в пределах текущего сеанса.
